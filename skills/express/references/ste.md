# STE 风格的应用

ASD-STE100 是 Simplified Technical English（简化技术英语）规范。Express 借鉴其减少歧义的写法，用于中文和英文的日常会话及文档。它不分发标准正文或词典，也不声称符合性认证。

## 用到每次沟通里

| 原则 | 实际做法 | 保留的边界 |
|---|---|---|
| 名称明确、含义稳定 | 同一对象沿用同一名称，必要术语就地解释 | 不把不同业务对象强行统一，不改错页面名或代码标识 |
| 动作具体 | 写出谁对什么做什么，减少“进行相关处理” | 主体或机制未知时说明未知，不补造 |
| 思路可跟随 | 一句围绕主要意思，一段围绕一个主题，保留连接关系 | 不按固定字数拆中文，不把复杂推导切成互不相接的短句 |
| 条件清楚 | 操作条件先于依赖动作，区分全部满足、任一满足、互斥分支 | 不把建议补成准入条件，不凭空增加阈值或重试次数 |
| 要求与说明可区分 | 必做要求、可选动作、背景解释各自表意准确 | 不把“可能”“建议”“预计”改成事实或承诺 |
| 阅读成本合理 | 先回答主问题，再给必要依据；选择能讲清关系的载体 | 不以字数少、表格少或形式检查通过代替质量 |

这些方法用于技术解释、任务分析、进度、澄清与完成答复，不限于正式文档。普通闲聊和一行答案无需增加专业模板。

## 复杂任务先讲清关系

输出前确认主问题有直接回答。多系统、多对象、多阶段场景中，先给读者可用的整体关系，再展开必要细节。不同方案用一致的判断维度；共同依赖要在所有受影响的方案中落实。

操作说明可按“条件→动作→已知结果”组织；机制解释可按“对象→关系→为什么”组织；方案比较围绕读者正在决定的差异展开。这些是组织选择，不是每个回答必交的固定栏目。

## 中文与英文不套同一把尺子

中文以完整意思、清楚指代和自然段落为判断依据。不用英文空格分词统计中文，也不另设未经证明的中文字符上限。英文可以保留必要时态、被动句和可能性表达，以含义准确为前提改善可读性。

“采用部分 STE 原则”是风格选择，不应包装为“达到 80% 合规”之类可量化保证。具体用户要求严格遵循正式标准时，应先取得适用版本及材料，确认用途与验证范围，不能用本 Skill 代替标准审校。
