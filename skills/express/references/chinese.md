# 中文表达与语义保真

中文清楚与否，取决于重点、对象、逻辑和读者是否能使用。不要按英文词数拆中文，不以某种标点、句长或禁词命中数判定质量。

## 用具体内容组织语言

- 开头直接给与读者问题有关的结论及理由，不反复复述任务，也不先讲做了多少次检索。
- 用读者熟悉的完整名称，必要缩写首次解释。准确的页面、按钮、字段、接口和专业名词保留原样，不为了“通俗”改错名称。
- 同一对象用同一名称。不要为避免重复交替使用“账号”“用户”“成员”，除非它们在当前材料中确实指同一对象。
- 动词说明真实动作。“完善能力”“赋能业务”“形成闭环”没有讲清事实时，改写为有依据的动作、对象和结果；原文没有这些信息时，定位缺口，不能自己填满。
- 消除指代歧义。“它”“该方案”“相关人员”可能指向多个对象时，写出名称。已知责任不模糊，未知责任不补造。
- 用完整段落承接因果、转折与限定。条件多时拆分或用列表；不要逐句断行制造短促、翻译腔式表达。

## 保留对判断有影响的语气

| 原文表达 | 应保留的含义 | 常见失真 |
|---|---|---|
| 可能改善、初步发现 | 证据有限，结果尚未确定 | 改成“将改善”“证明有效” |
| 建议、可选 | 提议或可选择的动作 | 改成“必须”“已决定” |
| 目标、计划、预计 | 目标或预期，具有各自前提 | 写成既成事实或无条件承诺 |
| 仅在……时 | 生效范围有限 | 为简洁删掉条件 |
| 尚未验证、原因未明 | 已知的证据边界 | 为主动语态补责任人或原因 |
| 当前不支持、暂不纳入 | 当前状态或本次范围 | 扩大成长期能力结论或永久禁止 |

“需要”“应当”在不同上下文中可能是正式要求，也可能只是建议。核对来源与语境，不一律升级或降级。数字相同也不等于含义相同，例如“成功任务数”与“应处理输入数”是不同分母。

## 格式与阅读

中文正文使用自然的中文标点；代码、网址、路径、原文引用和界面标签保留准确形式。中英文混排以可读性和现有规范为准，不破坏标识符。若使用中文破折号，写作“——”；不强制使用，也不把标点当作 AI 痕迹的证据。

小段内容不必加标题。较长内容用有信息量的标题和段落分层；并列内容、顺序动作和比较可以用列表或表格，但不能为了版式凑数量或空栏目。缩短后的文本仍要让无上下文读者知道每个数字、代词和动作指什么。

## 英文与双语

用户要求英文成稿时，直接写自然英文，保持领域术语准确。可借鉴稳定术语、清楚动作、条件先于依赖动作的原则；不硬套 ASD-STE100 词表、词数、语态或时态限制。

不得把 `may`、`might`、`could` 或 `should` 一律换成 `will`、`must`。保留事实、可能性、建议和义务的区别。无依据的主体未知时可以保留被动句。

双语版本按同一份事实和决定核对：范围、条件、数字、否定、建议强度和承诺必须一致；两种语言可以按自然语序分别组织。用户只要一种语言时，不默认输出双语。
