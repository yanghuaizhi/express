# Express · 清楚表达

让 Codex 从首次回复就尽量讲清楚：先回答问题，再讲清必要的依据、对象关系和条件，让读者能够理解、判断或行动。

中文优先设计，同时支持英文与双语内容。采用 ASD-STE100（简化技术英语）启发的表达原则，保留自然中文、必要信息和不确定性。覆盖日常会话、复杂任务与工作文档。

[English](README.en.md) · [使用规则](skills/express/SKILL.md) · [中文示例](skills/express/references/examples.md) · [安装与生效](docs/codex.md)

## 改善什么

- **首次回答**：问什么先答什么；复杂解释讲清对象、关系和取舍；进度说明当前结果和差距。
- **自动纠正**：用户说“没看懂”“太绕”“重点不清”或“信息不全”时，检查事实、推导、缺失信息和呈现方式，修正相关结论，无需再次点名 Skill。
- **工作文档**：围绕读者的判断和使用组织内容，补齐已有材料中分散的必要信息，保留成立条件和重要分支。
- **中文表达**：自然段落、具体动词、稳定术语，减少套话和翻译腔。必要的“可能”“建议”“尚未验证”必须保留。
- **修改边界**：局部修改不扩成重写，建议不变成决定，未知信息不编成数字、原因、期限或承诺。

简单答案可以很短，复杂内容可以展开。列表、表格和图按需要使用；纯解释不强加行动清单。

## 在 Codex 中使用

希望日常沟通也采用这些原则，推荐安装插件。它在受支持的会话启动事件中加载共同原则，复杂解释和表达纠正再按需使用详细 Skill。已经加载的原则直接应用，不在每次回复前重新读取或宣布启用。

在下载或克隆后的项目根目录执行：

```bash
codex plugin marketplace add .
codex plugin add express@express-marketplace
```

随后通过 Codex 原生界面审阅并信任启动 hook（会话开始时执行的脚本）；CLI 可用 `/hooks`。插件安装成功不代表 hook 已获信任。需要 `python3`；详见[安装与生效](docs/codex.md)。

两种入口选一种即可：

| 方式 | 适合什么情况 | 实际生效方式 |
|---|---|---|
| 安装插件（推荐） | 日常会话默认采用共同原则 | 原生信任启动 hook 后加载共同原则；详细 Skill 按需使用 |
| 单独安装 Skill | 先试用，或宿主不支持 hook | 用 `$express` 调用；自动匹配由 Codex 决定，不能保证每轮应用 |

**单独试用 Skill**：下载或克隆本项目，在项目根目录执行以下命令。目标已存在时命令不会覆盖，应先检查已有版本。

```bash
mkdir -p "$HOME/.agents/skills"
test ! -e "$HOME/.agents/skills/express" && cp -R skills/express "$HOME/.agents/skills/express"
```

单独安装后可在 Codex 中输入：

```text
$express 本次会话请直接回答核心问题，保留必要依据和条件，复杂关系用合适的结构讲清。
```

插件方式启用后，可以直接提出任务或反馈，不必加 `$express`：

```text
我没看懂这几个对象的关系，请用普通中文和一个例子解释。
把这些材料整理成供评审使用的方案，区分事实、决定和建议。
只改这一段的表达，保留原意与全部限定。
```

单独复制 Skill 不会安装 hook。宿主加载了规则，仍需用实际回复验证效果，不能承诺所有模型、客户端及已打开会话都会立即改变。

## 和 Waza Write 怎样配合

Express 不依赖 Waza。两者共存时，Express 的共同表达原则持续适用，具体任务只走一套主要流程：日常解释和表达纠正使用 Express；需要作者风格、本地化或专项稿件编辑时，沿用适用的写作 Skill。不会默认先写一遍、再交另一 Skill 重写。

Waza Write 本身也覆盖结构与中文写作，存在能力重合。Express 不复制或修改其上游流程，避免为共存长期维护分叉。具体边界见[共存说明](skills/express/references/compatibility.md)。

## 为什么另做一个项目

Express 借鉴 ASD-STE100 相关项目中稳定术语、明确条件与动作、减少歧义的思路。它不把面向英文技术说明的词数、语法限制直接套到中文，也不靠删除不确定性让表达显得果断。

核心规则与示例独立编写。详细来源及取舍见[来源与设计边界](docs/sources.md)。Express 不分发 ASD 标准或词典，不提供 ASD-STE100 符合性认证。

## 维护与验证

Skill 本身只需 Markdown。可选的启动 hook 需要 `python3`，只读取包内规则并输出上下文，不读取会话记录、不访问网络、不写用户文件。安装与更新不会修改用户的 `AGENTS.md`。

结构及协议检查：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python tools/validate.py
.venv/bin/python -m unittest discover -s tests -v
```

这些检查证明打包和程序行为，不证明沟通质量。内容验收需要看实际答复：是否直接回答问题，事实与限定是否保留，必要信息是否足够，读者是否能理解或使用。提供[独立虚构案例与评审依据](evals/README.md)，支持按相同输入检查变化；不以字数、禁词、标题数量或模型自评代替验收。

反馈请提供脱敏输入、实际输出和具体问题。不要上传私人会话、凭证、内部业务数据或本机配置。公开教学案例应独立编写并标明虚构。
