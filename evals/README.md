# 行为评估

这些案例检查 Express 是否帮助读者理解、判断或行动，并保留事实、语义和任务边界。它们不是 ASD-STE100 合规测验，也不是按字数、禁词、标题或语气打分。

[cases.json](cases.json) 提供 8 个独立编写的虚构输入，其中 5 个会话案例、3 个文档案例。[rubric.md](rubric.md) 提供逐例评审依据。案例不对应真实个人、公司或项目，作答需要的事实均在输入中。

## 覆盖什么

| 案例 | 重点 |
|---|---|
| C01 | 完成率分母、业务输入与已生成任务的区别 |
| C02 | 对象关系、连续示例、演示值与事实分离 |
| C03 | 方案取舍、硬条件与未知、建议身份 |
| C04 | 多轮纠正、共同前提、相关方案与澄清 |
| C05 | 进度与实际可用性、反馈分母、未验边界 |
| D01 | 局部修改、最新稿、已删除要求 |
| D02 | 无对话背景的评审文档、事实与建议归属 |
| D03 | 中英双语、同时满足条件、时长与费用范围 |

## 怎样评审

1. 固定模型、推理设置和共享任务上下文，记录所用版本。不要把评审标准、另一组答案或既有胜负提供给作答方。
2. 对照实验中，一组使用共同基线，另一组增加待评规则。两组使用相同输入。比较完整方案时应包括实际常驻规则，不把完整 Skill 与只有一句提示的基线混为一谈。
3. 隐去分组身份，随机安排答案顺序，按 rubric 指出具体优点、问题及其对读者的影响。允许无明显差异，不强制选赢家。
4. 发现问题后改规则，只回归受影响的行为。回归证明的是该问题在这些输入下的表现，不计作新的独立优胜样本。
5. 再用获准使用的真实任务检查迁移效果。未经单独披露授权，不把私人会话、项目内容或模型服务凭证提交到公开仓库。

可单独检查三个层面：答案是否正确、读者是否更容易理解、自动加载是否在目标客户端发生。显式把规则传给模型，只能用于前两个层面；不能据此宣称 Skill 自动调用或启动 hook 已经生效。

## 已知证据与局限

开发阶段对早期候选做过一次同模型对照：`gpt-6.1-sol / xhigh`，8 个虚构案例，两组答复由独立评审在隐藏分组身份后比较。6 例未见明显差异，1 例偏好候选，1 例偏好基线。样本量小、没有重复采样，基线也有通用沟通要求，结果不支持宣称稳定优于已有规则。

早期候选在纠正预约方案时，没有充分说明“锁位能力未知”同样影响人工方案。现有规则明确要求检查共同前提对所有相关方案的影响。该输入随案例保留，用于定向回归；不能因修改了规则就认定问题已被彻底解决。

针对 C04、C05 的新版回复已做定向回归，独立评审未发现违反各自输入的遗留问题。[回复与逐例评审](regression.json)保留完整结果。它验证的是这两次回复，不代表所有未来回答；测试时显式加载了规则，也不证明客户端自动调用已经发生。

上述是开发观察，不是当前版本的效果排名或通过率。本仓库不附带服务凭证或联网评分程序；可以使用现有模型环境生成答复并独立评审。结构检查与协议测试的范围见主 [README](../README.md)，宿主集成的验证方法见 [Codex 说明](../docs/codex.md)。
